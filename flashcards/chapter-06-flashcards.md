## Chapter 6: Feature Engineering, Splitting, and Avoiding Data Leakage — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Correct order of operations to avoid data leakage when scaling/encoding features? | Split data FIRST (train/test), then fit() transformers only on the training set, then transform() both train and test using the fitted parameters. Exam tip: fitting before splitting is the #1 tested leakage trap. |
| 2 | Spark ML: does df.randomSplit() support a stratify parameter like sklearn's train_test_split? | No. Spark ML has no built-in stratify argument. Achieve stratification by filtering each class into its own DataFrame, calling randomSplit() on each subset with the same weights/seed, then union() the results. |
| 3 | Correct syntax for a reproducible 80/20 split in Spark | train_df, test_df = df.randomSplit([0.8, 0.2], seed=42) — always pass a seed for reproducibility; the exam tests recognizing missing seed as a flaw. |
| 4 | StringIndexer vs OneHotEncoder — what does each do? | StringIndexer converts string category labels into numeric indices, ordered by descending frequency (most frequent label = index 0). OneHotEncoder then converts those numeric indices into sparse binary vectors. They must be used in that order. |
| 5 | OneHotEncoder default behavior: dropLast parameter | dropLast=true by default — the last category is dropped and represented as an all-zero vector to avoid multicollinearity. Exam tip: know this is the DEFAULT, not something you must configure to get. |
| 6 | StandardScaler vs MinMaxScaler — when to use which? | StandardScaler centers to zero mean and scales to unit standard deviation (good for algorithms assuming normal-ish distributions, e.g. linear/logistic regression). MinMaxScaler rescales to a fixed range, [0,1] by default (good when a bounded range is required, e.g. neural nets). |
| 7 | How does Pipeline.fit() vs PipelineModel.transform() relate to avoiding leakage? | pipeline.fit(train_df) learns all stage parameters (indices, means, coefficients) ONLY from training data, returning a PipelineModel. Call pipelineModel.transform(test_df) to apply those exact learned parameters to test data — never refit on test data. |
| 8 | Correct approach for splitting time-series data for model evaluation | Sort by timestamp and split chronologically (e.g., earliest 80% = train, latest 20% = test). Never use randomSplit() on time-series data — it shuffles rows and leaks future information into training. |
| 9 | VectorAssembler — what is its role in a Spark ML Pipeline? | Combines multiple numeric columns (and one-hot vector columns) into a single 'features' Vector column, which is the required input format for Spark ML estimators like LogisticRegression or RandomForestClassifier. |
| 10 | StandardScaler constructor default parameters | withMean defaults to False, withStd defaults to True. So by default StandardScaler only scales to unit variance and does NOT center to zero mean unless withMean=True is explicitly set. |
| 11 | Estimator vs Transformer in Spark ML — core distinction | An Estimator implements fit() and learns parameters from data, returning a Model (Transformer). A Transformer implements transform() and applies already-learned parameters to a DataFrame without learning anything new. |
| 12 | Why fit a scaler/encoder AFTER splitting instead of before? | Fitting before splitting lets test-set statistics (mean, std, category frequencies) influence the transformation applied to training data — a form of data leakage that inflates validation/test performance unrealistically. Exam tip: this is the most heavily tested leakage scenario. |
